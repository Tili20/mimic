# AGENTS.md — Mimic

Rust/GTK4/GIO приложение для управления MIME-типами и ассоциациями приложений.

## Правила согласия (критично)

Без **прямого и явного** согласия пользователя запрещено:

- Запускать любые команды (`cargo`, `git`, shell-скрипты, бинарники и т.д.).
- Записывать, изменять, удалять или создавать файлы на диске (включая временные).
- Коммитить, пушить, менять ветки или выполнять любые git-действия.
- Устанавливать зависимости и запускать приложение.

Согласие действует только на ту задачу, которая была одобрена. Новые действия —
новое согласие. Если команда/запись необходимы — сначала спросить, потом выполнять.

## Работа по TODO.md

1. Перед началом читать `TODO.md` и брать **один** невыполненный пункт (`[ ]`).
2. Выполнять строго одну цель за раз. Не смеживать пункты, не «заодно» допиливать.
3. По завершении цели — остановиться и доложить пользователю:
   что сделано, какие файлы затронуты, как проверено.
4. Не отмечать пункт `[x]` без подтверждения пользователя, что цель достигнута.
5. Если цель оказалась объёмной — остановиться и предложить план, не продолжать самовольно.

## Тесты

- Любой новый функционал обязан сопровождаться тестами (`#[cfg(test)] mod tests`
  рядом с кодом или в модуле, где реализована логика).
- Перед сдачей задачи: `cargo test` — обязан пройти.
- Исправление бага — сначала тест, воспроизводящий баг (если это возможно без UI).

## Команды проверки (запрашивать разрешение на каждый запуск)

```sh
cargo build            # сборка
cargo test             # тесты
cargo clippy -- -D warnings   # линтинг, без предупреждений
```

Код считается готовым только когда все три проходят чисто.

## Стандарты кода

- Писать читаемый, понятный, логичный код: имена говорят сами за себя,
  функции короткие и с одной ответственностью, без магических чисел и мёртвого кода.
- Следовать существующим конвенциям проекта (см. `src/`): стиль, именование,
  структура модулей, идиомы gtk-rs/glib-rs.
- Комментарии — только там, где намерение не очевидно из кода. Не дублировать код словами.
- Новые зависимости — только после согласования (править `Cargo.toml`).
- Держать слои раздельно: `backend.rs` (данные/GIO) ≠ `model.rs` (модель) ≠ `ui.rs`/`chooser.rs` (интерфейс).
- Не рефакторить код, не относящийся к текущей цели, — глобальный рефакторинг отдельный пункт TODO.

## Структура проекта

- `src/main.rs` — точка входа
- `src/backend.rs` — работа с GIO: MIME-типы, приложения, установка дефолта
- `src/model.rs` — `MimeType` (`glib::Object` с `#[derive(glib::Properties)]`)
- `src/ui.rs` — главное окно, список, фильтры, вкладки
- `src/chooser.rs` — окно выбора приложения
- `data/` — desktop-файл и иконка
- `packaging/` — упаковка (Arch и др.)
- `kdeMimes.md` — референс поведения KDE (§5–6 — «Other…»)
- `plan.md` — исходный план проекта
